{% comment %} Type-ahead results for picking baths onto a sheet, and the fourth click behaviour on the one `product_search` endpoint. **Adding is an htmx swap of the list, and a form submit when it isn't.** The `hx-get` sends the current list (`hx-include="#sheet-list"`) plus one `add` and swaps back the sheet fragment — a few hundred bytes, no page reload. The `form="sheet-list"` and `name="add"` underneath are what the same click does with the script blocked: submit the list form with one more parameter. One button, both paths, and no JavaScript of our own in either. The list is server-side state carried as hidden `items` inputs in that form, which is why the button needs to say nothing about what is already there. `add=` rather than another `items` entry, because the two would fight: a row posts `items=:` *and* a `qty-` box, so a second `items` for something already listed gets summed and then overwritten by the box's older number — the add silently does nothing, which is how this arrived. No SKU filter here, unlike the label list: a SKU prints a sticker, it doesn't dye a bath. The oven tick rides in `#sheet-list`, which `hx-include` sends with the add — so a `+` on an oven run stays on an oven run without this template knowing anything about it. {% endcomment %} {% comment %} **Two states, and the line between them is who decided.** An undyed passthrough and a fancy veil cannot be dyed at all, so those stay disabled — facts about how the thing comes into being.
